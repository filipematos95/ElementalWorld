## 1. Executive overview

**What this file is.** `hybrid_ecosystem.py` defines one class, `HybridEcosystem` (line 5), which is a self‑contained, TensorFlow‑accelerated **agent‑based ecosystem simulation engine**. It has no dependency on Streamlit, no plotting code, and no file I/O — it is a pure computational/model layer. It is designed to be imported and driven by an external script (most plausibly a Streamlit app, per the project context) that (a) constructs a `HybridEcosystem` instance with scientific and numerical parameters, (b) seeds it with initial organisms via `add_initial_seeds`, (c) calls `.step()` repeatedly to advance the simulation clock, and (d) calls the `get_*` methods to pull out state for visualization.

**Main scientific process represented.** A spatially explicit, multi‑species population dynamics model in which:
- Organisms ("agents") occupy cells of an `H × W` lattice.
- Each organism has a body mass and an **elementome** — a compositional (fractions summing to 1) vector over a fixed list of chemical elements (default: C, N, P, K, O, Ca, Mg, S, Fe, Mn, Zn).
- Each species has a preferred elementome ("niche center") and a tolerance (covariance) around it; an organism's **fitness** is a bounded function of the Mahalanobis distance between its current elementome and its species' niche center (`_compute_niche_fitness_mahalanobis`, line 583).
- Organisms grow by drawing carbon internally (proportional to their own current carbon fraction) and other elements from a shared, diffusing, spatially heterogeneous soil nutrient pool, subject to Michaelis–Menten saturation and a Liebig "law of the minimum" stoichiometric limitation.
- Organisms respire, senesce/turn over biomass into the soil, die (from a minimum‑viable‑mass threshold and from several optional periodic disturbance/catastrophe mechanisms), and reproduce clonally by producing dispersed offspring ("seeds") that inherit the parent's *current* (not idealized) elementome.
- Soil nutrients cycle between an inorganic (plant‑available) pool and an organic (litter/detritus) pool via mineralization, with exogenous nutrient input, diffusion, and occasional localized disturbance events.
- A sinusoidal global temperature signal, spatially perturbed by a persistent noise field, modulates growth, respiration, and mineralization rates.

**Main computational process represented.** A fully vectorized (no Python‑level per‑agent loop), TensorFlow‑graph‑compiled (`@tf.function`, line 226) update of a fixed‑capacity agent buffer (a `(MAX_AGENTS, AGENT_WIDTH)` tensor, line 135–138) and a `(H, W, 2·N_soil)` soil‑state tensor (line 123–126), executed once per call to `step()`. This is the standard "structure‑of‑arrays as one big matrix" pattern used to make agent‑based models GPU‑parallelizable.

**Inputs.** All scientific and numerical parameters arrive as constructor keyword arguments (there are ~45 of them; see Section 14) — none are read from a config file or Streamlit widget *inside this file*. Two arguments (`niche_centers`, `niche_covariances`) are required and have no defaults; their concrete values, shapes, and biological meaning are entirely external to this file.

**Outputs.** In‑memory TensorFlow `Variable` state (`self.soil`, `self.agents`, `self.n_agents`, `self.env_field`, `self.shock_field`, `self.temperature`, `self.step_count`, `self.last_deficit`) plus a plain Python list (`self.death_fitness_log`). Nothing is written to disk. Downstream consumption happens exclusively through the `get_*` methods, which return NumPy arrays or Python scalars.

**Relationship to the Streamlit application.** Inferred, not confirmed: this class is almost certainly instantiated once per simulation configuration inside a Streamlit script, with `.step()` called inside a loop (e.g., driven by a "Run" button or `st.session_state`) and the `get_*` outputs fed into `st.pyplot`/`st.line_chart`/`st.image` or similar. None of this is visible in the file itself.

**Relationship to the larger simulation.** This file appears to be the *entire* dynamical core of the elemental‑organism simulation described in the project brief: lattice, agents, species, elementomes, environment, growth, mortality, interactions, and reproduction are all implemented here. The only clearly external pieces are (a) the UI/configuration layer and (b) whatever supplies the numeric values of `niche_centers` and `niche_covariances`.

**Classification.** This file mixes several of the roles listed in the brief and should **not** be classified as a single type:
- **Agent definition** — the agent buffer schema (`I_Y`…`I_AGE`, `AGENT_WIDTH`, lines 45–53) and `add_initial_seeds`.
- **Lattice / spatial engine** — soil diffusion (lines 232–239), coordinate handling, periodic/reflective boundary logic.
- **Environmental‑process module** — `env_field`/`shock_field` (lines 187–195), temperature (lines 197–203, 300–303).
- **Population‑dynamics module** — the growth/uptake/mortality/reproduction core of `step()` (lines 226–548), which is by far the largest and most scientifically consequential part of the file.
- **Output/utility module** — the `get_*` diagnostic methods (lines 550–697), which are lightweight, read‑only, eager‑mode accessors.

There is **no visualization code** and **no configuration‑file handling** in this file.
